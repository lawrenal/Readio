# Architecture

- **Stack:** Next.js 16 (TypeScript, App Router) full-stack app. SQLite +
  Prisma (`@prisma/adapter-better-sqlite3` — Prisma 7's client needs an
  explicit driver adapter at runtime).
- **Capture:** paste-a-link form (`/`) + a Chrome extension
  (`extension/`, load unpacked). Both hit `POST /api/items`. URLs are
  normalized (strip `www.`, tracking params, trailing slash) and deduped
  before insert.
- **Extraction** (`src/lib/extract*.ts`) runs inline on submit — no job
  queue, deliberately, since this is a personal tool and a fetch/
  transcript call taking a few seconds is fine. Articles: fetch +
  `@mozilla/readability`. YouTube: transcript via the `youtube-transcript`
  package + title via YouTube's public oEmbed endpoint (no API key for
  either). A failed article fetch flags the item `needs_pdf` — print the
  page to PDF and upload it as a fallback, extracted via `pdf-parse`. A
  YouTube video with no transcript just fails; no fallback.
- **Grounding/anti-hallucination** (`src/lib/ai.ts`, `episode.ts`):
  two-pass generation. A per-item pass produces a summary/key-facts/tags
  record once an item is extracted. A nightly (or weekly) pass gets every
  item's summary, key facts, *and full extracted text* as grounding,
  clusters them, and writes the script — instructed to state only what's
  in the supplied source text and name the source before covering it, so
  every claim is traceable. Falls back to a plain template writer (no
  real clustering) when no AI provider is configured, or if the call
  fails, so the rest of the pipeline still runs — see
  `src/lib/episode-script.ts`.
- **Editable prompts** (`src/lib/prompts.ts`, `/settings` → Prompts):
  the system prompts for script-writing (daily and weekly separately)
  and the episode teaser summary are all editable from the browser — a
  saved override fully replaces the built-in instructions, not just
  appends to them. The two script prompts use
  `{{maxWords}}`/`{{maxMinutes}}` placeholders, filled in automatically
  at generation time. See [prompts.md](./prompts.md).
- **AI provider** (`src/lib/llm.ts` + `ai-{anthropic,openai,xai,gemini,openwebui,ollama}.ts`):
  six providers behind an `LlmProvider` interface, selected via
  `AI_PROVIDER`. OpenAI, xAI, Open WebUI, and Ollama (direct) share one
  Chat Completions client (that wire format is near-universal, and it's
  Ollama's own built-in API too); Gemini uses Google's own `interactions`
  endpoint. See [ai-providers.md](./ai-providers.md) for setup and which
  are actually verified against a real key.
- **TTS** (`src/lib/tts.ts` + `tts-{elevenlabs,azure,google,gemini,kokoro,kokoro-remote}.ts`):
  behind a `TtsProvider` interface, selected via `TTS_PROVIDER`. Long
  scripts are chunked and the resulting audio concatenated — raw byte
  concatenation for the mp3 providers (safe, since mp3 is frame-based),
  no chunking for Gemini (its WAV output isn't safe to concatenate that
  way), sentence-level chunking for Kokoro. Audio content-type/extension
  is derived from the file actually on disk, not the currently active
  provider, so episodes generated by different providers over time all
  still serve correctly. See [tts-providers.md](./tts-providers.md).
- **The daily episode** (`buildDailyEpisode` in `src/lib/episode.ts`):
  clusters/narrates everything extracted since local midnight, ≤45
  minutes.
- **The weekly deep dive** (`buildWeeklyEpisode`, same file): a separate
  generation path sharing the daily episode's clustering/grounding
  pipeline via a common `generateEpisodeFromItems()` helper, but drawing
  from currently-**starred** items instead of "today's new content," with
  a 90-minute budget and a prompt framed around going deeper on fewer
  items. Runs alongside the nightly cron every Saturday. See
  [scheduling.md](./scheduling.md).
- **Settings** (`/settings`, `src/lib/settings.ts`): every env var this
  app reads for user-tunable config is registered in one place and
  editable from the browser. A saved value lives in a `Setting` database
  table and overrides the matching env var — absent a saved override,
  the env var (or a built-in default) still applies, so a plain
  `.env`-only deployment keeps working unchanged. Changes take effect on
  the next request/read (no restart), except `ENABLE_SCHEDULER`/
  `NIGHTLY_CRON`, which are only read once at server startup — the UI
  flags those two explicitly. Secret-type values (API keys, the
  basic-auth password) are encrypted at rest if `SETTINGS_ENCRYPTION_KEY`
  is set — see [security.md](./security.md).
- **Access control** (`src/proxy.ts`): an optional, off-by-default HTTP
  Basic Auth gate in front of the entire app, toggled live from
  `/settings` — no restart needed. Runs as Next.js 16's `proxy`
  convention (the renamed `middleware`), which defaults to the Node.js
  runtime, so it can read the live setting from the database directly on
  every request rather than needing some Edge-compatible workaround. See
  [security.md](./security.md).
- **Delivery:** a private podcast RSS feed at `/feed.xml`, built fresh
  per-request from the request's own origin (works over localhost, LAN,
  or a Tailscale/Cloudflare Tunnel hostname without config) + `/audio/[id]`
  with Range support for scrubbing/resuming in podcast apps, plus an
  inline `<audio controls>` web player on the home page.
- **Hosting:** Docker (`Dockerfile`, `docker-compose.yml`) is the primary
  path — self-contained (ffmpeg, Kokoro's model, the SQLite db, and the
  nightly scheduler are all handled inside the container), with an
  in-process nightly scheduler (`src/instrumentation.ts` + `node-cron`,
  opt-in via `ENABLE_SCHEDULER=true`) instead of an OS-level cron.
  `launchd/` has an alternative always-on-server + 9pm-trigger setup for
  running natively on a Mac without Docker.
- **Starring:** a boolean on `Item`, toggled via a ☆/★ button — feeds the
  weekly deep dive. A "Starred for this week's deep dive" section
  appears on the home page whenever at least one item is starred, for
  browsing/managing the queue without scrolling through the full item
  list. Items unstar themselves automatically once covered by a deep
  dive.
- **Edge cases:** local timezone, rolling midnight-to-midnight day as the
  cutoff for "today's content." No new content = no daily episode that
  day. The length cap (45/90 min) is a soft target (steered via the
  script prompt's word-count instruction), not a hard cutoff — audio is
  never truncated mid-sentence.
- **Responsive UI:** single-column layout (`max-w-2xl`, centered) that
  scales from phone to desktop without a separate mobile view.

## Known gaps

- Only Anthropic and Open WebUI have been verified against a real
  generated episode. OpenAI, xAI, Gemini, and Ollama-direct are built but
  untested against a real key/instance — see
  [ai-providers.md](./ai-providers.md).
- Only local Kokoro and remote Kokoro (mlx-audio) have been verified with
  real synthesized audio. ElevenLabs, Azure, Google, and Gemini TTS are
  built but untested against a real account — see
  [tts-providers.md](./tts-providers.md).
- No automated hallucination-check pass on generated scripts — the
  grounding approach (full source text passed in, explicit "only state
  what's here, name the source") does real work, but there's no second
  pass that verifies the final script actually honored those
  instructions.
- No multi-user support, no per-user API keys — this is a single-user,
  local-config tool by design.
- Non-YouTube video, email/SMS capture, and a native mobile app are all
  unbuilt, no current plans.
